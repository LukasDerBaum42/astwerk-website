A multilingual site is the same site with different text. astwerk treats it that
way: a locale's subtree is **generated from the base tree**, and you list only
the pages that genuinely differ.

## BuildLocales

```go
root = ssg.BuildLocales(root, []ssg.Locale{{
	Code:   "de",
	Prefix: "/de", // defaults to "/" + Code
	Override: map[string]func(ssg.Node) ssg.Node{
		"": func(n ssg.Node) ssg.Node {
			n.Title, n.Page = "Meine Seite", ssg.Templ(views_de.Home)
			return n
		},
		"projects": func(n ssg.Node) ssg.Node {
			n.Generate = projectsFrom("content/i18n-de/projects")
			return n
		},
	},
}})
```

| Field | Meaning |
| --- | --- |
| `Code` | language code and mount directory — `de` → `/de/…` |
| `Prefix` | URL prefix handed to pages as `Ctx.Prefix`; defaults to `"/" + Code` |
| `Override` | patches for the nodes that differ, keyed by path relative to the locale root |

`""` as an override key is the locale's own home page.

Everything not named in `Override` — every other page, including generated
collection children — appears under `/de/` on its own, rendered by the same
components with `Ctx.Prefix` set to `"/de"`. Given a base tree with
`about`, `goals`, `links` and `projects`, the four lines above produce nine
German pages.

## Why derived rather than declared

The obvious API is a `Tree func() ssg.Node` per locale. It was tried and thrown
out: it *forces* duplication, because the only thing you can hand it is a whole
subtree restating the structure you already wrote. Every page added to the base
tree then has to be added again per language, and the two drift.

Deriving inverts that. The default is "the same site", and an override is an
exception you opt into.

## Two rules worth knowing

**Assets are not inherited.** `CopyFrom` and `CompileFrom` are dropped when
deriving a locale subtree. Stylesheets, images and scripts are shared across
languages and served from the site root — without this rule you'd get
`build/de/style/` duplicating every asset per language. A locale that genuinely
needs its own asset — a localized screenshot — sets the field back in an
override.

**An override is a function over the node, not a replacement for it.** It
receives the node `BuildLocales` would otherwise have derived at that path, so
changing one field is one line and nothing you don't touch is lost:

```go
"about": func(n ssg.Node) ssg.Node {
	n.Title = "Über mich"
	return n
},
```

That page keeps its `Page` function, its `Files` and its children. Replacing
them wholesale is the same shape, just assigning over more fields — it's a plain
Go function, so there are no merge semantics to learn and no reflection doing it
behind your back. This applies at the locale root too: patching `""` keeps the
inherited children because they're already sitting in `n`, not because of a
special case.

A key with no counterpart in the base tree gets the zero `Node`, which is how a
page that only exists in one language gets written:

```go
"impressum": func(n ssg.Node) ssg.Node {
	return ssg.Node{Title: "Impressum", Page: ssg.Templ(views_de.Impressum)}
},
```

## Threading the prefix

`Ctx.Prefix` and `Ctx.Locale` are set for every page in a locale subtree, and
`Ctx.Link` applies the prefix for you:

```templ
templ Nav(c ssg.Ctx) {
	<a href={ c.Link("projects/") }>Projects</a>
	<a href={ c.Link("about/") }>About</a>
}
```

Rendered in the base tree that's `/projects/`; in the German subtree it's
`/de/projects/`. Same markup.

## A language switcher

Use `Ctx.InLocale`, which returns this page's URL in another language:

```templ
templ LocaleSwitch(c ssg.Ctx) {
	<a href={ c.InLocale("") }>English</a>
	<a href={ c.InLocale("/de") }>Deutsch</a>
}
```

It works because a locale subtree mirrors the base tree, so the same page exists
at both paths.

Do not build this from `Ctx.Path` by hand. `Path` already contains the current
locale segment, so re-prefixing it gives `/de/de/about/`. `Ctx.Rel` is the
locale-independent form if you need it directly — `"about/"` whether the page is
at `/about/` or `/de/about/`.
